# Hardware Fixer (FRX)

[Português (Brasil)](README.pt-BR.md)

[![CI](https://github.com/gustavomfg/FRX/actions/workflows/ci.yml/badge.svg)](https://github.com/gustavomfg/FRX/actions/workflows/ci.yml) [![Release](https://img.shields.io/github/v/release/gustavomfg/FRX)](https://github.com/gustavomfg/FRX/releases) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

**Hardware Fixer** is a desktop app that **fixes hardware on Linux laptops**: Wi-Fi, audio, touchpad, suspend and firmware. It identifies the laptop model from DMI, searches the **Arch Wiki** for that model and, when the page gives a clear instruction (a module option, a kernel parameter), shows an exact preview of the change in `/etc`, with backup and undo.

> **FRX never runs `sudo`.** To change `/etc`, it makes a backup, stages the file in a private folder and shows the command for you to run in a terminal. Before overwriting anything, the command itself checks, as root, that the file has not changed since the preview. Afterwards, FRX verifies the resulting hash in `/etc`. Undo works the same way.

## Install

Download the latest release from the [Releases page](https://github.com/gustavomfg/FRX/releases). Each release has three packages:

| Package | For |
| --- | --- |
| `.AppImage` | Any distribution. Make it executable (`chmod +x`) and run it. |
| `.deb` | Debian, Ubuntu, Linux Mint and derivatives: `sudo apt install ./<file>.deb` |
| `.rpm` | Fedora, openSUSE and derivatives: `sudo dnf install ./<file>.rpm` |

**Arch Linux, CachyOS, EndeavourOS, Manjaro:** build the native package from the repository (see [How to run](#how-to-run)): `npm run build:arch`, then `sudo pacman -U packaging/arch/frx-bin-*.pkg.tar.zst`.

> **Status: early release (0.5).** What the app can fix depends on what the Arch Wiki documents for your model. If it finds no fix for your laptop, or a fix helps (or does not), please open a [laptop report](https://github.com/gustavomfg/FRX/issues/new?template=laptop-report.yml).

## How it works

1. **Identification.** Vendor, model and board come from `/sys/devices/virtual/dmi/id` (no privileges; serial number and UUID are never read). Generic firmware strings ("To Be Filled By O.E.M.", "System Product Name"…) count as missing. On Lenovo, the commercial name comes from `product_version` (`product_name` is the machine type code).
2. **Symptoms.** The home screen shows your system (model · GPU · kernel) and five symptoms: Wi-Fi, Áudio, Touchpad, Suspensão and Firmware.
3. **Arch Wiki search.** Through the public MediaWiki API, at most two cached requests: the model search and the matched page's text. A page is only accepted when every number in the model matches ("Gen 9" never becomes "Gen 10"). The symptom's sections, the hardware table status ("Funciona segundo a wiki") and the general page for the symptom are extracted. Arch Wiki content is GFDL 1.3+, shown as a quote with a link.
4. **Applicable instructions.** A strict parser only recognizes unambiguous instructions: `options <module> <key=value>` and kernel parameters in a sentence that says to apply them. Negative sentences ("does not work"), commands and unit names are discarded. Instructions with conditions ("only on Intel", "if…") are flagged and require an explicit acknowledgement.
5. **Preview and apply.** "Aplicar correção" (apply fix) opens the Fix Engine preview: the file in `/etc`, its exact content, checks, backup, side effects (reboot, initramfs) and the `sudo` command. After running it, "Já rodei — conferir" (I ran it — verify) checks the hash. Fixes are listed under **Correções no sistema** (system fixes), with "Desfazer" (undo).

### Supported system fixes

| Action | File | Notes |
| --- | --- | --- |
| Module option | `/etc/modprobe.d/frx-<module>.conf` | New FRX file; warns if another file already configures the module |
| systemd service | `/etc/systemd/system/frx-<module>-sleep.service` | Fixed template (reload the module around suspend); no free-form `ExecStart`. Not generated by the parser yet |
| Kernel parameters | `/etc/default/grub` | Changes only the `GRUB_CMDLINE_LINUX_DEFAULT` line; high risk. Without GRUB, the card shows "Incompatível" |

Parameters that change the boot target or disable protections (`init=`, `rd.break`, `mitigations=`, `selinux=`…) are never applied.

## Security

- **Closed write allowlist.** `confined.rs` only opens `/etc/modprobe.d/frx-*.conf`, `/etc/systemd/system/frx-*.service` and `/etc/default/grub` for writing. Every directory is opened with `O_NOFOLLOW`; symlinks, hard links, special files, traversal and directories swapped between preview and write are refused.
- **No automatic `sudo`, no `pkexec`, no `sed -i`.** FRX does not execute any privileged command. Commands that overwrite or remove an existing file go through `sudo sh -c` with `sha256sum --check` against the hash read at preview: if the file changed, nothing is modified. This closes the window between showing the command and you running it.
- **Verified on disk.** A fix only counts as applied (or undone) after FRX verifies the hash in `/etc`. A pending fix can be cancelled from its dialog without touching the system.
- **The UI only sends IDs.** Symptom, suggestion and action; the core redoes the search from cache, recomputes the preview and compares the fingerprint before anything else.
- **Restricted network.** HTTPS to a closed list of hosts (including redirects), bounded response size, ETag cache. External content is text, never HTML or code.
- Backups, journal and staged files live in `~/.local/share/io.frx.FRX/fix-engine/` (0700 directories). Cache in `~/.cache/io.frx.FRX/`.

## How to run

A **Tauri 2** (Rust) desktop app with a React + TypeScript + Vite interface. The interface is in Brazilian Portuguese; labels below are quoted as they appear.

### Build dependencies

- Node 20.19+ or 22.12+ and npm
- Rust **1.88+** via [rustup](https://rustup.rs)
- WebKitGTK libraries:

| Distribution | Command |
| --- | --- |
| Arch/CachyOS/Manjaro | `sudo pacman -S --needed webkit2gtk-4.1 gtk3 base-devel curl wget file openssl librsvg` |
| Debian/Ubuntu | `sudo apt install libwebkit2gtk-4.1-dev libgtk-3-dev build-essential curl wget file libssl-dev librsvg2-dev` |
| Fedora | `sudo dnf install webkit2gtk4.1-devel gtk3-devel openssl-devel curl wget file librsvg2-devel && sudo dnf group install c-development` |

### Commands

```bash
npm install
npm run dev            # opens the window (Tauri + Vite with live reload)
npm run build          # release binary + AppImage, .deb and .rpm
npm run build:arch     # native pacman package (Arch/CachyOS)
npm run build:web      # type-checks and builds the interface
npm test               # front-end tests (Vitest)
(cd src-tauri && cargo test)                         # Rust tests (fixtures, no network)
(cd src-tauri && cargo clippy --all-targets -- -D warnings)
(cd src-tauri && cargo test -- --ignored)            # live tests: Arch Wiki and reading the real /etc
```

In the browser (`npm run dev:web`) there is no system access; the interface asks you to open the desktop app.

### Testing on a desktop (development fixture)

Debug builds only: the home screen shows **"Injetar laptop de teste (dev)"**. It simulates only the DMI identity; the search hits the real Arch Wiki and the Fix Engine is the real one (manual mode, nothing written to `/etc`).

- **Framework Laptop 13:** has applicable instructions. Under **Wi-Fi**, `options iwlwifi disable_11ax=Y`; under **Suspensão**, `nvme.noacpi=1` (shown as "Incompatível" on a machine without GRUB).
- **ThinkPad X1 Carbon Gen 9:** has a wiki page, but no applicable instruction in the symptom sections.
- "Voltar ao DMI real" (or restarting the app) ends the simulation.

### Desktop integration

- The app id and window class are `frx` (`StartupWMClass=frx` in the `.desktop` files).
- On tiling window managers (Hyprland, Sway…), add a rule for class `frx` if you want the window floating.
- **WebKitGTK + NVIDIA on Wayland:** the app sets `WEBKIT_DISABLE_DMABUF_RENDERER=1` at launch unless you already set it.

## TypeScript ↔ Rust bridge

| Command | Purpose |
| --- | --- |
| `identify_laptop` | Vendor, model, board and display name from DMI (or the test laptop, in debug) |
| `get_system_profile` | Distribution, kernel, session, CPU, RAM, GPUs and drivers |
| `search_hardware_fixes` | Arch Wiki search for a symptom, with each action's light check |
| `prepare_system_fix`, `apply_system_fix` | Preview of an instruction and confirmation (IDs and the preview fingerprint only) |
| `list_fix_operations`, `verify_fix_operation` | History and on-disk verification |
| `prepare_fix_rollback`, `rollback_fix` | Undo preview and execution (or cancelling a pending fix) |
| `get_fix_providers`, `clear_fix_cache`, `get_cache_size` | Sources and cache |
| `set_dev_laptop` | Debug only: test laptop |
| `app_info` | App and system information for the settings screen |

## Structure

```
src-tauri/src/
  system/                  dmi (laptop identity), hardware (GPUs and drivers)
  fixes/                   http (cache, rate limits, ETag), models, providers/arch_wiki (search + instruction parser)
  fix_engine/              confined (allowlist and descriptor-pinned writes), system (system actions,
                           preview, guarded commands), journal, files, models: apply and rollback
  commands/                hardware, system, fix_engine, app, dev_laptop (debug)
  net.rs, cache/, time.rs  HTTPS client with a closed host list, cache, clock helpers
src/
  pages/                   Dashboard (system, symptoms, results), Settings, NotFound
  components/hardware/     SuggestionCard, SystemFixDialog, ChecksList, symptoms
  state/hardware.tsx       laptop identity and system profile
  services/                native (IPC bridge), hardware, fixEngine
  design/tokens.css, mascot/   visual identity and Pim
```

## Visual identity and accessibility

- Colors live in `src/design/tokens.css`, exposed to Tailwind (`bg-surface`, `text-fg-2`, `text-accent`…); alternative accents in Settings.
- **Pim**, the mascot, is drawn procedurally on a 24×20 grid (`mascot/sprites.ts`) and reacts to what happens on screen.
- Animation intensity **Full / Soft / Off**, honoring `prefers-reduced-motion`. Visible focus, focus-trapped dialogs, `aria-live` on results; status never relies on color alone.
- Shortcuts: `Ctrl + K` (pages and symptoms), `Alt + 1/2` (Home, Settings), `Esc` (closes dialogs, except during an operation).
