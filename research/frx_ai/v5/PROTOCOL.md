## Questions and controls

1. Audit v4's literal result patterns, grammatical evidence, direction morphology and annotation unit. Preserve all old labels. Version any new agent interpretations; model disagreement is not a correction oracle.
2. Compare v4, a simple local lexical baseline, and deconstruction into event trigger / argument / modality / observation / association. Test a pretrained compact dependency parser as structural evidence, rather than a generic outcome classifier.
3. Compare small trained atomic statement verifiers and syntactic reconstruction. Mark the target operation and bound its evidence. Separate outcome observation from its owner; multiple actions can own a joint reported result, never separate causal credit.
4. Compare comment retrieval against structured incident retrieval using the same v2 encoder and context. Unknown versus incompatible context differs. No positive result crosses game/build/GPU/driver/Proton/configuration boundaries. A cross-game case is at most an explicitly attributed hypothesis.
5. Evaluate next-check selection using immutable public report/request snapshots and separately declared controlled telemetry masks. Prefer literal logs to speculative cause classification. No numeric real-game posterior without fitted, justified likelihoods; compare complexity with simple log-directed checks.

## Data and evaluation

Old v1-v4 final sets are known development/audit data. Reserve new AppIDs/discussions before body inspection. Split training/development by game and discussion; no synthetic example derived from a final comment. Freeze code, selected artifact hashes, thresholds and comparison criteria before annotating the final source bodies or making their predictions. If new experiments use the final results, they require a new independent cohort.

All new labels are provisional research-agent annotations, with no independent human review. Retain original full source hashes, paragraph offsets, literal event/observation spans and ambiguous/joint ownership. Do not infer file identities from descriptions, GPU use from detected hardware, game technology from GPU support or a DLL filename, or causality from temporal order. Corrective operations, diagnostic collection and gameplay/reproduction need separate roles.

Primary comprehension metrics: strict character-IoU >=0.5 trigger matching; performed precision/recall with actual counts; status and direction; supported owner-group/result edges; false success/false performed claims; argument hallucinations; abstention and source quote integrity. Match an association only when its owner/group and literal result overlap are correct. Publish unaccepted proposals separately. A useful gain requires nontrivial coverage, a material paired improvement over v4/simple controls and no concealed serious error class. Do not claim >=90% from fewer than 30 accepted assertions across four games; even that floor is not population validation.

Diagnostic metrics: appropriate next-check@1/@3, grounded milestones, unknown-cause recognition, contradiction/context handling, duplicate thread groups, repeated failed attempts and provenance. Evaluate entire replay trajectories, not just final labels. Separate public historical cases, agent-selected questions, public maintainer requests, and synthetic/masked controls. Never present a snapshot replay as a newly executed game incident.

Keep trained configurations, decoding/control readouts, regression fixtures and engineering tests counted separately. Report resource usage and risk/coverage trade-offs; do not treat zero claims as success. No experimental output authorizes the Fix Engine.
